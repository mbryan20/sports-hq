# Q-017 · The last four rebases become merges

Drafted by the nightly improvement pass, 2026-11-05. Nothing here is built until the item's Decision says approved.

## Problem
ROADMAP "Rules that must not break" (line 117): "always merge, never rebase (`git pull --no-rebase --no-edit`); the repo
has subtree merges." `git grep -n -- --rebase .github` still finds 4 spots on Nov 5:
- `.github/commit_data.sh:8` `git pull -q --rebase -X theirs` (every Sports HQ pass, up to every 10 min)
- `.github/workflows/war-room-v2.yml:48` `git pull -q --rebase -X theirs`
- `.github/workflows/picks-backup.yml:67` `git pull --rebase`
- `.github/workflows/yahoo-reauth.yml:41` `git pull -q --rebase`
Already merging: `model-health.yml:47`, `feedback.yml:44`, `picks/pp/publish.py:72` (fixed since the review).
A rebase across a subtree merge can replay the subtree's history or fail, and it rewrites the job's own commit.

## The trap: `-X theirs` flips meaning
In a rebase, "theirs" is the commit being replayed, i.e. the job's own fresh data. In a merge, "theirs" is the remote.
Swapping `--rebase -X theirs` for `--no-rebase -X theirs` would make every data conflict keep the *older* remote file
and throw away the pass that just ran. The merge equivalent of today's behaviour is `-X ours`.

## The change
1. `commit_data.sh:8` and `war-room-v2.yml:48`:
   `for i in 1 2 3; do git pull -q --no-rebase --no-edit -X ours && git push -q && exit 0; sleep 5; done`
2. `picks-backup.yml:67` and `yahoo-reauth.yml:41`: `git pull -q --no-rebase --no-edit && git push -q` (no conflict
   strategy today, and none added: the backup only runs when the laptop's card is missing, and the token file has one
   writer, so a real conflict should stop the job and alert rather than pick a side). Give both the
   same 3-try loop as the data jobs, since a single failed push loses a backup card or a refreshed token.
3. A guard so it doesn't come back: `tests/test_repo_rules.py` (new) fails if `git grep -n -- "--rebase" .github picks shq`
   finds anything other than `--no-rebase`.
4. ROADMAP "Git" rule: add one line, "data loops use `-X ours` (keep this pass's data on a conflict)".

## Risks and rollback
- More merge commits in the history (only when two jobs push in the same few seconds). Cosmetic.
- `-X ours` resolves only conflicting hunks; a non-conflicting change from the other side still merges in, as rebase did.
- Rollback: revert the commit; behaviour returns to today's rebases.
