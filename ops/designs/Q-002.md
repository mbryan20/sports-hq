# Q-002 · War Room v2 locks games already played and rebuilds during game days

Drafted by the nightly improvement pass, 2026-11-07. Nothing here is built until the item's Decision says approved.

## Problem
From the first kickoff until Monday night ends, War Room v2's week `W0` (`D.week`) is the week in progress, but `model.js`
`proj(s, W0)` is Sleeper's pre-kickoff projection for every player, `lineup()` re-picks a best lineup from the whole roster
(players already played or benched included), and `swing(W0)` is the full team swing (22). `model.py` `build()` never
fetches the current week's Sleeper matchups (`starters`, `players_points`). The dashboard does: `shq/guillotine.py`
`entry()` keeps a final game at its real points with SD 0, a game in progress at max(points, projection) with half SD,
and `lineup()` keeps started starters in their slot and bars started bench players from open slots.
It also barely rebuilds then. The only Thu-Mon slot in `war-room-v2.yml` is "daily 6:10am CT", and it has run 6-9.5 h
late (Nov 1-6 runs started 11:54am-3:40pm CT; Sunday Nov 1's landed 6 minutes before kickoff). Nothing runs on Sunday
afternoon/night or Monday before MNF; the Mon 10:40/11:20pm slots come after the week is final and look ahead.
Stored history (read-only replay tonight): v2 has bids.json versions only since Oct 31 and none taken mid-games. The
dashboard (lineups.json, every 10 min on game days) gave week 8's cut team drewpepin1 1.9% Thursday, 2.3% at 11:57am CT
Sunday, 96.1% at 7:07pm CT Monday. So a Sunday-morning check moves little (only Thursday's game is locked); the gain
shows Sunday night and Monday. `gd.v2_skill` and `gd.dash_skill` both score the snapshot before the week's first kickoff.

## The change
1. `warroom/model.py` `build()`: fetch `matchups/{W0}` (the same Sleeper endpoint the dashboard reads via
   `sleeper.matchups`) and reuse `espn.games(SEASON, W0)`, which `played_week()` already calls. Add `D.live` =
   {starters by roster, {player: [points, "in"/"post"]} for players whose game has started} (empty before kickoff).
2. `warroom/model.js` (W0 only, when `D.live` has entries), copying `guillotine.entry()`/`lineup()`:
   - `lineup(roster, W0)`: started starters keep their slot at real points (final) or max(points, projection) (in
     progress); started bench players can't fill open slots; open slots take the best unstarted players as today.
   - per-team W0 swing = `S.sd` × sqrt(share of that lineup's projected points still to play); `simulate()` takes it as an
     optional per-team override for W0 only. Later weeks unchanged.
   - `candidates()`/`bestDrop()`: a free agent whose game has started adds 0 for W0; started players aren't W0 drops.
3. `exportBids()`: add `live` (games final, my points so far) to `me` and each `cut_risks` row; `data_as_of` says
   "live: games through Sun 3:25pm CT locked". `app.js`: the KPI reads "Wk 9 cut risk (live)" when locked.
4. Builds during games: the Sports HQ run loop (run.yml, every 10 min on game days) dispatches `war-room-v2.yml` with
   `gh workflow run` when a game has gone final since the last v2 build (needs `actions: write` in run.yml; a
   GITHUB_TOKEN dispatch does start the workflow). Keep one writer of docs/war-room-v2. Back-up crons: Sun 11:30am,
   3:45pm, 7:30pm CT and Mon 6:30pm CT.
What changes: Thu-Mon, v2's page and bids.json cut risks match the live state. Tuesday output is unchanged (no game has
started), so the 6:00am strategy task and 7:11am bid check see no difference. v2 sends no pushes; the cut-risk push stays
the dashboard's until Q-011.

## Risks and rollback
- Sleeper's mid-game points get stat corrections; only "post" games get SD 0, and the Monday-night final rebuild resets.
- More v2 runs (about 10 per game week) and more commits to docs/war-room-v2; the run-loop trigger must debounce.
- Not confirmed: whether Sleeper lets a started player be dropped mid-week (step 2 assumes not).
- Rollback: ignore `D.live` in model.js (one flag) and drop the dispatch step; the page returns to pre-kickoff numbers.
