# Q-067 · Tap "Fixes now" for the list; Skip and comment on every advice line

Drafted by the nightly improvement pass, 2026-11-16. Nothing here is built until the item's Decision says approved.

## Problem
Michael's feedback, Nov 15 (issue #5, Domo Arigato detail on his phone, 402px): "No where to say skip or comment on what I
think about something. Also, on the main part if I click on fixes I'd like to be taken to some sort of screen or
presented with a pop up that shows what needs to be fixed". In the code today:
- The "Fixes now" KPI (`docs/index.html:75`) is a plain div. The fixes only appear one league at a time, in each drawer.
- Only Fix now lines have a button (Clear, Q-063). Lineup moves, Waiver adds, the Weekly start/sit and trade ideas have
  none. Skips exist only on HQ's own fantasy cards (`docs/data/decisions.json`, Nov 14); the site lists them under
  "You skipped" but can't make one.
- Feedback is per tile (👍/👎) or per page (💬), so he can't say which line is wrong.

## The change
1. **Fixes list (layout A, then B-D).** `docs/index.html`: the "Fixes now" and "Lineup moves" KPIs become buttons
   (`data-open="fixes"` / `"moves"`). `openLeague` gets those two keys: the drawer shows `SHQ.actionsHTML(kind)`, a new
   `core.js` function over `S.feed()` filtered to that kind, grouped by league (league name links to `#lg=<league>`),
   each line with Clear (fixes) or Skip (moves). Empty: "Nothing to fix. Lineups are set." Hash `#lg=fixes` so back
   closes it. Same drawer on B-D through the shared function.
2. **Skip on every advice line.** In `S.detail` the existing `clr()` button is reused for Lineup moves, Waiver adds,
   trade offers and the Weekly start/sit, labelled "Skip". Tapping opens a small reason picker (Bad advice / Already
   handled / Not worth it / Not now: the same codes as `shq/decisions.py`, codes only because the repo is public),
   hides the line on this device at once, and opens the pre-filled GitHub issue as Clear does today, with the reason
   code and the line's kind in the body.
3. **One pipeline.** `shq/cleared.py` records `kind` and `reason` (default `fix`/`handled` for old entries) and
   `drop()` filters moves, adds and offers too; the build already calls it for Today and the texts
   (`shq/digest.py:221`). Matching for moves and adds uses `shq/decisions.py`'s tested key ("start|a|b", "add|a|b")
   instead of the letters-only problem key, so a changed projection doesn't bring a skipped move back but a different
   player does. The league page's "You skipped" list shows site skips and HQ skips together (Undo for local ones).
4. **Comment on a line.** A 💬 button beside Skip opens the existing feedback form (`fbOpen`) with the spot set to
   "<league>: <first 60 chars of the line>", so FEEDBACK.md records which advice he meant.
5. **Docs:** the What's new page and glossary get one line each; README "Feedback" section.

What Michael sees: tap "Fixes now: 3" → a sheet listing all three with their leagues, Clear on each, and a link into the
league; every move/add/trade line has Skip and 💬; skipped lines leave the page, Today and the texts on the next build.

## Test before shipping
- `tests/test_cleared.py`: a skipped move key matches the same move with a new projection or slot, not one with a
  different player; old cleared.json entries (no kind) still filter fixes; `drop()` leaves other leagues alone.
- `tests/test_decisions.py` style cross-check: the browser and Python keys agree on 20 real lines from today's
  lineups.json (moves, adds, NBA swaps, offers).
- Replay: last 7 days of `docs/data/lineups.json` from git with one fake skip per league: exactly that line disappears
  from page, digest items and texts; the next-best move takes its place (count stays the same when one exists).
- Browser (Playwright, 375 and 402px, light and dark): the KPI opens the sheet, Back closes it, no horizontal scroll,
  tap targets at least 40px (Q-046's rule), Skip and 💬 don't open the league drawer underneath.
- No health.json check moves; the one-off Measure is Michael's next feedback on layout A.

## Risks and roll back
- Over-broad matching could hide a different move: the decisions key is already tested on his real HQ lines; the
  sheet shows every hidden line with Undo.
- A Skip still needs him to tap Create on GitHub to reach other devices (as Clear does). Not changed here.
- Roll back: revert the commit; cleared.json entries with kind other than `fix` are ignored by the old code.

M: about a day of UI and one small Python change, plus tests.
