# Q-072 · Dynasty add lines show the add's value but not the drop's (feedback #8)

## Problem
Michael, site feedback #8 (2026-11-19, 3-Ball FB, comment on "Add Malik Washington (WR, MIA, 9.9/gm, value 1,190)
for Treylon Burks (WR, your WR7, 6.8/gm)"): "does this make sense from a dynasty perspective? no dynasty analysis or
trade-off presented." `shq/waivers.py` `line()` prints `value {fa['val']}` for the add and only position, depth and
ppg for the drop. The answer was in our own data (players_nfl.json at cd5d8765, 3-Ball FB): Washington FantasyCalc
dynasty 1,190, Burks 441, so the swap gains +749 dynasty value and +2.3 pts over 4 weeks. The page never says it.
The ranking already uses it (`adds()`: `rank = window + (fa.val − drop.val) / 250` in dynasty), and Domo's draft-pick
mode filters on it (`draft_race.keep_add`, +250 rule), but neither shows the number, so the 250 rule can't be
checked from lineups.json either (Q-069 evidence, Nov 18-20).

## The change
1. `shq/waivers.py` `line(a)`, dynasty leagues only (`adds()` stores `dynasty` on each result dict next to `depth` and `cuff`): after the drop's ppg,
   add the drop's value and the net, e.g. "for Treylon Burks (WR, your WR7, 6.8/gm, value 441): fills in at WR in
   weeks 11, 14, +2.3 pts over the next 4 weeks; dynasty +749 (1,190 vs 441)". When the net is negative, say it
   first: "costs 320 dynasty value for +2.3 pts over 4 weeks" so a points-for-future swap is never silent.
   Redraft leagues unchanged (their value is a tiebreak, not an asset).
2. Same text in Domo's draft-pick mode (it uses `line()` already), which makes the +250 rule visible.
3. `docs/lib` needs nothing: the line is a string; the Players page already has the `fc` column.
4. No change to which adds are suggested. Whether a dynasty swap should ever give up value for points is a rule
   question for Michael (fantasy-rules.md), not part of this item; the design only shows the trade-off.

Data needed: none new (`fa["val"]`, `drop["val"]` are already on both dicts).

## How to test before shipping
- Unit tests next to the handcuff ones in `tests/test_handcuff_football.py` (they already build `waivers.adds` rosters): a dynasty swap with a gain, one with a loss, a redraft swap (unchanged text),
  an open-spot add (no drop: no net), a K/DEF stream (unchanged).
- Replay: rebuild the add lines from the last 14 days of `docs/data/lineups.json` commits for 3-Ball FB and Domo with
  the new `line()`; every dynasty swap line must carry both values and a net equal to `fa.val − drop.val` from that
  commit's players_nfl.json. Count how many past suggestions had a negative net (report it in the commit message);
  that count is what Michael needs to decide the rule question in point 4.
- No health.json check moves; one-off Measure: the next live 3-Ball FB and Domo add lines show "dynasty ±N".

## Risks and roll back
Low. Longer lines on a 402px phone (about 25 characters more); check one league page at 375-402px. Roll back = revert
the one `line()` change.
