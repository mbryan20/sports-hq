# Q-008 · Rivals' gains net of the player they would have to drop

Drafted by the nightly improvement pass, 2026-11-13. Nothing here is built until the item's Decision says approved.

## Problem
`warroom/model.js` `rivalGain(t, s)` (line 125) adds the freed player to the rival's roster and compares lineups, with
no drop. Rosters are full, so a rival must drop someone. Usually that is a bench player who doesn't start, and the
gain is the same; but a rival whose bench is all bye fill-ins or his only backup QB/K/DEF loses something, and the model
overstates his need. Since Q-062 (Nov 12) the same number feeds the rival-by-rival model's need tiers (`rivalInputs`,
`build.py` `need_tier`: under 1, 1-3, 3-6, 6+ lineup points a week), which set each rival's claim chance. Because the
claim chances are fitted on these same inputs, a bias that is the same every run is partly learned away; one that
varies by rival or week is not. Size unknown: nothing measured yet.

## The change (only if step 1 shows it matters)
1. Measure first: in `rivalInputs`, also compute the net gain with the rival's best drop (`bestDrop(t, s, null, true)`,
   which already exists for Michael's side) and count, over every past run's rival-player rows (`rival_model`'s n), how
   many change need tier. Write the count to the build log.
2. If 5%+ of rows change tier: `rivalGain` returns the net gain (`lineup(roster(t, [s], drop))`), `rival_model` is fitted
   on it, and the old `threats()` raw estimate uses it too.
3. If under 5%: reject the item with that number (Michael's call on the Decision line).
What Michael sees: possibly slightly lower claim chances for players only thin-benched rivals need, so a few lower bids.

## Test out of sample before shipping
- Q-064's time-forward check (or Q-062's replay if Q-064 isn't built): with net gains, `wr.rival_brier` must not get
  worse and the 50% price's coverage must stay within 0.05 of 0.5, on weeks 2-9 and on week 10 once it has run.
- `tests/test_warroom_revamp.py`: a rival with an all-starter roster gets a lower need than one with a spare bench.

## Risks and rollback
- `bestDrop` for 10 rivals x ~30 freed players per run adds build time (lineups are cheap; check under 2x).
- Rollback: one function back to the add-only gain.
