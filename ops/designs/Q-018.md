# Q-018 · One set of moves per league: never drop this week's starter, one source for this week's gain

Drafted by the nightly improvement pass, 2026-11-07. Nothing here is built until the item's Decision says approved.

## Problem
Nov 1 review (Guillotine at 375px): Bids said "No free agent adds a point to your lineup" while Waiver adds said "Add Bryce
Young … lineup +2.0/gm", and that add dropped J.K. Dobbins, whom Lineup moves said to start. Stempak and Bro-vid19 cited an
Oct 23 "ruled out" note on David Montgomery's IR-slot line. A replay tonight of all 327 committed `docs/data/lineups.json`
snapshots (Oct 31 to Nov 7 04:38Z, football leagues only) found:
- **Drop = this week's start, 4 players, 114 snapshots:** Kimani Vidal, Bro-vid19 (92, Nov 4-6: the fix says "Montgomery OUT
  → start Kimani Vidal", Waiver adds says "Add Bryce Young … for Kimani Vidal"); Dobbins, Guillotine (11, Nov 1); Tre Tucker
  (6) and Zach Charbonnet (5), Guillotine, Nov 3-4. Cause confirmed: `waivers.adds()` protects only
  `lineup(slots, roster)` (`waivers.py:116`), which `trades.lineup()` picks on rest-of-season `ppg`. An injured starter with
  a high ppg stays protected and the bench player covering for him this week (`swap.start_sit()` / `digest._fix()`, both on
  this week's `proj`) is droppable.
- **Guillotine Bids vs Waiver adds, 5 players, ~310 snapshots:** an add claiming "lineup +X/gm" that Bids didn't list
  (Bryce Young 208, Juwan Johnson 85, Brenton Strange 15, Jayden Daniels 4); last seen Nov 6 04:08Z. Two horizons: Bids
  (`guillotine.analyze()` → `bid()`, `guillotine.py:186`) uses this week's projected gain ≥ `MIN_GAIN` 1.0; Waiver adds'
  "lineup +X/gm" (`waivers.line()`, `waivers.py:190`) is the rest-of-season per-game gain. Neither says which it is.
- **IR line citing an old note, 3 cases:** Montgomery (Oct 23 note, Stempak and Bro-vid19, 104 snapshots each, to Nov 1
  22:47Z, up to 9 days old) and Rashid Shaheed (Oct 31 note on Nov 3, 2). `run.better_news()` only swaps in the latest ESPN
  headline when the injury-report note is under 30 characters (`run.py:68`), never when it's old.
- Related, same card: Bro-vid19 shows Waiver adds while its IR line says "ESPN blocks adds and drops" (233 snapshots,
  including today; Stempak 106 until Nov 1).
Today (Nov 7 04:38Z): 0 drop-vs-start cases, Bids and Waiver adds agree (both list the Saints DEF), the Shaheed IR line cites a
Nov 6 note. The code is unchanged since Oct 31 (`waivers.py` last touched in 46076da), so the bug is dormant, not fixed.

## The change
1. `shq/waivers.py` `adds()`: new `keep=()` argument (player ids). Line 116 becomes the ppg lineup **plus** `keep`, so the
   drop list (line 117) can't hold anyone I start this week. K/DEF streaming (lines 126-138) is untouched.
2. `shq/advice.py`: `build()` works out this week's starters before `adds()`: live starters (`not _dead(s)`) minus those a
   move benches, plus bench players named by `swap.start_sit()` (`_moves`) or picked by `digest._fix()`. `_fix()` already
   adds its pick to `league_items()`'s local `used` set; return that set (or keep it on the league) instead of parsing text.
   `adds(league)` passes it as `keep`.
3. Guillotine, one source for "this week": `guillotine.analyze()` also returns `gains` = {player id: this week's gain} for
   every free agent it scores (the `mine.gain(e)` it already computes, before the `MIN_GAIN` cut). In guillotine leagues
   `advice.adds()` reads `league.guillotine["gains"]` (set in `run.guillotine_odds()` before `league_view()`) and
   `waivers.line()` says both horizons: "this week +1.4 (see Bids)" or "no gain this week", then "rest of season +2.0/gm".
   Other leagues get the same "rest of season" label. `docs/lib/core.js:196` empty text: "No free agent adds a point to
   this week's lineup."
4. `shq/run.py` `better_news()`: also fetch `espn.player_news()` when the cited note is more than 3 days old
   (`STALE_NOTE_DAYS`), and keep whichever note is newer by date. Same hourly cache, so no extra ESPN load to speak of.
5. While an IR line is present, prefix Waiver adds with "After you move <name> out of IR:" (`advice.adds()`).
What the page shows: no add that drops a player the card says to start; guillotine add lines name this week's gain the same
way Bids does; IR lines cite the newest dated note. Lineup moves, fixes, Bids amounts and NBA tabs are unchanged.

## Risks and rollback
- A wider `keep` can leave no legal drop in small-bench leagues, so fewer adds; that's correct, and the replay counts it.
- `_fix()`'s pick is the bench player by `strength()`, which can differ from `start_sit()`'s pick; protect both.
- Old ESPN snapshots can't be re-run end to end (`values.annotate` reads today's FantasyCalc/projections and Sleeper is
  live), so the before/after relies on fixture tests plus forward replay, not a re-run of Nov 1.
- Rollback: `keep=()` (one argument), drop the `gains` read in `advice.adds()`, revert the `better_news` condition.
