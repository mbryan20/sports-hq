# Q-019 · A picks backup that can actually build a card, on time

Drafted by the nightly improvement pass, 2026-11-09. Nothing here is built until the item's Decision says approved.

## Problem
Since Nov 8 the laptop is the only pool picker: the cloud "Football pools picks" task was turned off after the
side-by-side (claude-audit `changes.md`, "Pools cutover check (Nov 8)"). If a laptop card run is missed, the only net is
`.github/workflows/picks-backup.yml`, and it has never built a card:
- **It can't build one.** Tonight, in a clean clone with no `CFBD_API_KEY` (as in Actions: `gh secret list` has only
  NTFY_TOPIC, TOKEN_KEY and 3 Yahoo secrets), `BACKUP=1 python -m pp.cards --stage draft` failed in 6 seconds:
  `RuntimeError: CFBD /lines not cached and no key/budget` (`pp/market.py:38` → `pp/http.py:48`).
- **It runs too late.** Its 8 runs (Oct 29-Nov 7) all started 4-8h after the slot: Wed 9:45pm slot ran Thu 5:31am CT
  (Nov 5), Thu 8:45pm ran Fri 3:52am (Nov 6), Fri 9:45pm ran Sat 4:40am (Nov 7), Sat 8:45am ran 1:02pm (Nov 7), after
  CFP's 11am lock. All 8 "succeeded" only because the laptop had posted and the build step was skipped.
- `picks-backup.yml:67` still rebases (`git pull --rebase`; Q-017 covers that line).

## The change
1. **Michael adds the secret** (his step, once): repo Settings → Secrets → Actions → `CFBD_API_KEY`, the same key as
   `picks/.env` on the laptop. Exact steps written when this is approved.
2. **Check inside run.yml's loop**, which now starts hourly from the laptop kick (Q-029) and every 10 min on game days:
   new `picks/pp/backup.py --if-due` (beside `pp.lines --if-due`, same "never fails the run" wrapper). For each slot
   (Wed 9pm draft, Thu 8pm BTO final, Fri 9pm final, Sat 8am refresh), it acts only when: now is 45+ min past the slot,
   the pool still has an unlocked game (reuse `pp.lines` lock times: BTO per game, CFP Sat 11am CT), `data/cards.json`
   `generated_iso` is older than slot − 2h (the existing freshness rule), and `state/alerts.json` has no
   `picks-backup:<week>-<stage>` key. Then: build with `BACKUP=1`, commit via `commit_data.sh`, one push (`push_once`).
3. **Keep `picks-backup.yml`** as the second net when the laptop is off (its crons still fire, late), with the same
   `--if-due` rules so both can't post twice, and its pull switched to merge (Q-017).
4. **Fail loud, not silent:** if a build fails, the push says why (e.g. "no CFBD key"), not just "failed".
5. **Q-021 note:** Q-021 untracks `picks/cache/cfbd/`; with the secret in place the backup fetches instead of relying on
   those files, so do this first or together.

## Test before shipping
- In a clean clone with the key: `BACKUP=1 python -m pp.cards --stage draft` and `--stage final` build a card with rows
  for Yahoo, BTO and CFP (no commit). Count CFBD calls used (`cache/cfbd_calls.json`); must fit the 900/month budget
  with room for 4 backups a week.
- Out of sample on this season: rebuild weeks 9 and 10's backup cards from the committed slates and compare with the
  laptop's posted cards (`picks/data/published/`): picks that match, and the ones that differ with the reason (missing
  research). Expect most to match, since the laptop card is market + research.
- `--if-due` unit tests: slot not reached, card fresh, pool locked, already sent → nothing; missed slot → one build.
- A forced `workflow_dispatch` with a `dry_run` input that builds but doesn't commit, then a week of logs with no
  double posts. No health.json check covers this (one-off: a forced backup builds a card).

## Risks and rollback
- A mistimed backup could overwrite a researched card (it happened Oct 30 with an age rule). Guarded by the slot-based
  freshness rule plus the lock check; the backup card is labelled "BACKUP (no fresh research)".
- CFBD budget: each build spends calls. Rollback: remove the `pp.backup` line from run.yml; the workflow stays as today.
