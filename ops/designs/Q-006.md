# Q-006 · The War Room v2 page shows the same calls as bids.json at default settings

Drafted by the nightly improvement pass, 2026-11-09. Nothing here is built until the item's Decision says approved.

## Problem
The page and bids.json run the same `warroom/model.js`, with the same seed (`rng(20261027)`, `model.js:74`), but at
different sizes: the page `S.sims = 6000` (`model.js:20`), so each add is compared at 3,000 seasons (`S.sims / 2`,
`model.js:166` and `:184`); `export.js:12` sets `S.sims = 20000`, so bids.json compares at 10,000. The Tuesday push and
the AI write-up read bids.json; Michael reads the page. Near the 0.003 win-odds floor (`MIN_WIN`, Q-009) the two can
disagree. bids.json now (Nov 8 17:53Z, 14 rows): Pat Freiermuth and Tyler Higbee "Add free" at +0.004, BAL DEF "Skip" at
+0.003 (rounded), NE DEF, BUF DEF and Dominic Zvada "Skip" at +0.002: 6 of 14 calls sit within 0.002 of the floor, where
the Nov 3 audit measured ±0.3-0.7 points of noise at 2,000 seasons. Not confirmed: how many differ on the page today
(Node isn't on the laptop to replay at 3,000).

## The change
Show bids.json's own results on the page whenever the settings are the defaults; simulate only when Michael changes one.
1. `warroom/build.py` `main()`: it already builds `bids` from the same `blob` as the page. Embed it in the page as
   `<script type="application/json" id="bids">` (new `__BIDS__` placeholder in `app_template.html`, escaped like
   `__DATA__`). Both files come from the same build, so they can't be out of step.
2. `warroom/app.js` `rerender()`: when every slider is at its starting value and no add is ticked, run the page's model as
   today (for the lineup, forecast and rivals tabs), then, for each bid row, take `call`, `bid`, `value`,
   `extra_win_odds`, `win_chance`, `bid_options` and `why` from the embedded bids by `sleeper_id`. Rows bids.json has and the
   page doesn't (or the reverse) are added/dropped to match its list. The header shows "20,000 seasons (same as the push)".
3. Any slider move or ticked add: today's behaviour at 6,000, with the header saying "6,000 seasons: calls within about
   0.002 of the floor can differ from the push". Reset returns to the bids.json view.
Alternative (not recommended unless a phone test says it is fast): run the page at 20,000 on first load. With the fixed
seed that reproduces bids.json exactly, but it is about 3x the work of today's first render on a phone.

## Test before shipping
- Unit test (Node, in Actions): build the page and bids.json from one committed `app_data` snapshot; in a headless run of
  the page at defaults, every row's call and bid equals bids.json's (0 differences); with one slider moved, the page
  recomputes and the header says so.
- Out of sample: the War Room v2 history has a bids.json per build since Oct 31 (`git log -- docs/war-room-v2/bids.json`);
  for each committed build, replay the page at 6,000 and count rows whose call differs from bids.json. That count is
  today's error rate (the one-off Measure); after the change it must be 0 at defaults.
- Timing: first render on the built-in browser's phone viewport no slower than today (it does the same work plus a lookup).

## Risks and rollback
- If the embedded bids and the page's own rows disagree on which players are listed, the page must follow bids.json and
  say so; a test covers it. Rollback: revert; the page goes back to its own 6,000-season calls.
